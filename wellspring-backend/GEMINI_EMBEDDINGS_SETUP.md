# Wellspring — Gemini Embeddings Setup

Wellspring uses **Groq for chat/safety/reflection** and **Gemini for embeddings**.

## Required Render environment variables

```env
GROQ_API_KEY=...
GROQ_CHAT_MODEL=openai/gpt-oss-20b

GEMINI_API_KEY=...
EMBEDDING_MODEL=gemini-embedding-001
EMBEDDING_DIMENSIONS=768

CORS_ORIGIN=https://wellspring-red.vercel.app
```

`GEMINI_API_KEY` is used only for vector embeddings. `GROQ_API_KEY` continues to power the LLM/chat pipeline.

## MongoDB Atlas vector indexes

Both indexes must use **768 dimensions**:

- `journal_entries_vector_index`
- `chat_messages_vector_index`

Run:

```bash
npm run create-vector-indexes
```

Then wait in MongoDB Atlas until both vector search indexes report `READY`.

## Re-embed existing data

Embeddings generated by the old provider/model cannot be mixed with the new Gemini embedding space. After the indexes are ready, run the one-time migration:

```bash
npm run reembed-all
```

You can control the delay between requests with:

```env
REEMBED_DELAY_MS=150
```

## Local development

Create `.env` from `.env.example`, then run:

```bash
npm install
npm run dev
```

## Production deployment

1. Add `GEMINI_API_KEY` to Render.
2. Set `EMBEDDING_MODEL=gemini-embedding-001`.
3. Set `EMBEDDING_DIMENSIONS=768`.
4. Redeploy Render.
5. Confirm `/health` returns `{ "ok": true }`.
6. Ensure Atlas vector indexes are `READY`.
7. Run `npm run reembed-all` against the production database.
8. Test chat.
